Alexandria is already a strong, distinctive product UI: a warm gold-on-parchment palette, Literata serif display type, a calm ease-out motion system, a 44-component kit, and a first-class dark theme. It does not read as AI-generated. The distance to award-winning is mostly systemic, not visual: a few real accessibility defects, no shared scale tokens, and thin state-pattern coverage. Close those and this is a genuinely award-grade writing studio.

BLive accessibility evidence

Run in a real Chromium via chrome-devtools. The dashboard scores a11y 100; the component showcase scores 84, surfacing defects in primitives that ship on real screens.

🎨 Color contrast (WCAG AA) P1

--text-faint on bg = 2.56:1 (light), 4.21:1 (dark). Needs 4.5. 86 nodes on one page.

white on danger fill = 2.97:1 (dark, destructive buttons).

Fix: darken --text-faint to ≥4.5:1 on both bg and surface, both themes; use a darker on-danger text (or deepen the danger fill). Add a CI contrast gate.

♿ ARIA defects in kit primitives P1

  • ProgressBar — role="progressbar" with no accessible name (3×). Add aria-label/aria-valuetext.
  • Tab — role="tab" buttons not wrapped in a role="tablist" parent (3×).
  • DiffPane — aria-label on a role-less <span> dot (prohibited, 2×). Use role="img" or visually-hidden text.

Why it matters: the axe unit-gate runs under jsdom (no layout), so contrast and required-parent slip through. A real-browser Lighthouse gate catches them.

CPriority backlog

Ordered by award-impact. Each maps to a phase of the approved program.

P1 Accessibility: AA contrast + ARIA fixes Phase 1/2

Darken --text-faint and the on-danger text to pass AA in both themes; fix ProgressBar / Tab / DiffPane ARIA. Award juries treat AA as table stakes.

P1 Scale tokens: type · spacing · radius Phase 1

Sizes are hardcoded (text-[13px], rounded-[10px]) across the kit and screens. Codify a scale into globals.css @theme (behavior-preserving first), then refine rhythm. This is the consistency multiplier for every future screen.

P2 State-pattern library + localized errors Phase 1

Add SkeletonCard/List/Table, a richer EmptyState (icon + copy + CTA), and an inline ErrorState (retry). Replace the raw Failed to fetch with friendly Hungarian copy. Adopt across codex/timeline/relations/plotlines/jobs.

P2 First-run onboarding: one path, not two Phase 2

The "how it works" modal stacks over the inline three-step banner on first load. Pick one (prefer the calm inline banner; demote the modal to an on-demand "?"), so a first-timer is not double-onboarded.

P2 Missing kit primitives Phase 1

A real Radix Select/Combobox (replace native <select> in cover + image panels), a loading button state, an Accordion, and input prefix/suffix slots.

P3 Motion, density & detail polish Phase 2

Per-screen micro-interactions, density tiers where useful, avoid nested cards (the first-run modal nests step cards), and a final pass on focus rings verified live.

DPersona red flags

Solo HU author (primary)
The raw English Failed to fetch breaks immersion and offers no recovery path; faint metadata text (2.56:1) is hard to read in daylight or for older eyes.
First-timer
A modal lands on top of the onboarding banner: two explanations of the same first steps at once. Icon-only left rail needs hover to learn.
Power user
Well served: Cmd+K, slash menu, shortcuts overlay, focus mode. Missing: bulk actions and a real combobox for fast model/style switching.

EWhat is already working

  • Distinctive, on-brand identity (warm parchment + gold + Literata serif). Passes the AI-slop test.
  • Complete light and dark token system with a smooth themed transition.
  • Disciplined motion: ease-out only, 120–260ms, reduced-motion safe by construction.
  • 44-component kit with CVA variants and an axe unit-test gate; honest empty/error states on the dashboard.
  • 11 genuinely polished screens (Write/Tiptap, Plan board, Codex, Timeline, Relations, Plotlines, Research, Jobs, Projects, Settings, Markdown export).

FV1 readiness & recommendation

MVP is 100% complete; much of V1 too, and cover generation (Phase 2) just landed. The remaining V1 gaps are modest and mostly UI completion.

Remaining for V1

  • Fill the placeholder screens: Áttekintés + Prompt Library (hangok stays V2).
  • PDF export (Markdown/DOCX/EPUB already work).
  • CodexProgression editor + timeline overlay (CRUD exists).
  • Plotline lane visualization (CRUD/list exist).
  • Ollama in-app model download in Settings.
  • E2E unblock: resolve the app Python package-name collision.

Recommendation

Do not jump to V2. Land the accessibility + design-system foundation (Phase 1), apply the per-screen polish (Phase 2), then close the handful of V1 feature gaps (Phase 3). That ships a coherent, AA-clean, award-grade V1. V2 themes (audio domain, collaboration/Auth.js, marketplace) come after.
