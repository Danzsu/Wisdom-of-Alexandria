ForgeWriter AI — Architekturális megközelítés

Ez az egyik legtöbbször visszatérő alapdöntés: hol fut az app, és mit tárol hol?

A

Local-first: Docker Compose

Az eredeti terv szerint: minden fut lokálisan. Next.js + FastAPI + PostgreSQL + Qdrant + Redis + Ollama egy docker-compose.yml fájlból.

Előnyök

  • Kézirat nem kerül felhőbe
  • Nincs havi cloud számla
  • Ollama GPU közvetlen elérés
  • Teljes adatvédelem

Hátrányok

  • Telepítés bonyolultabb
  • Nincs multi-device sync
  • GPU konfig gépenként különbözhet
B

Cloud-first: Vercel + Neon + Qdrant Cloud

Frontend Vercelre, Neon serverless Postgres-re, Qdrant Cloud-ra. Ollama csak opcionális lokálisan, fő modell API-n (Gemini/OpenAI/OpenRouter).

Előnyök

  • Egyszerű deployment
  • Bárhonnan elérhető
  • Nincs Docker konfiguráció
  • Neon auto-scale és branch

Hátrányok

  • Kézirat felhőbe kerül
  • Cloud modell = API cost
  • Nincs valódi offline mód
  • Neon + Qdrant Cloud havidíj
C

Hibrid: Docker dev → Vercel-ready prod

Fejlesztés Docker Compose-ban, de az architektúra legyen Vercel/cloud-ready is. Neon Postgres lokálisan is futhat, Qdrant self-hosted marad. AI réteg: Ollama lokálisan + cloud API switch.

Előnyök

  • Mindkét world best-of
  • Helyi fejlesztés egyszerű
  • Deployolható Vercelre is
  • Adatvédelem megőrizhető

Hátrányok

  • Két konfig karbantartása
  • Kicsit több setup
Megjegyzés

A projekt célja local-first, lokális Ollama futtathatóság — ezt a Vercel+Neon opció gyengíti. Ha a cél az egyszerű demo/kipróbálás is, a hibrid C a legjobb kompromisszum.
